# Инструкция агенту, который адаптирует микрохарнесс

1. Прочитай `README.md`, `SOURCE-MAP.md` и README выбранного блока. Сначала выясни, какую конкретную задачу команды нужно решить.
2. Используй синтетические данные до получения собственных доменов, репозиториев, получателей и правил доступа от владельца. Не переноси реальные заявки, токены, chat ID, закрытые URL и внутренние скриншоты в публичный git.
3. Для общего блока зафиксируй точный SHA родителя и отдели обязательную структуру от настроек экземпляра. Не редактируй сгенерированный HTML как первичный источник.
4. Для редактора сохраняй изменения в источнике с проверкой ревизии и понятным откатом. Публичный доступ требует отдельной аутентификации и проверки прав.
5. Для бота различай `accepted`, `dry_run`, `delivered` и `failed`; успешный HTTP-запрос не доказывает доставку сообщения.
6. Для QA показывай дату проверки, commit SHA, статус каждой проверки и доказательства. Если проверка не запускалась, ставь `unknown`.
7. Перед передачей проверь локальный запуск, ошибки, мобильную ширину и исходные файлы. Отдельно сообщи, что проверено локально, что закоммичено, что опубликовано и что подтверждено в живой системе.

Не меняй действующие `kit/`, `web/` или инфраструктуру AI Mindset без отдельной задачи владельца. Этот набор — учебный исходник.
