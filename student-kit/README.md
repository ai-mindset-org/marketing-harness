# Микрохарнесс: сайт, лиды, страницы и QA

Это учебный набор для маркетинговой команды. Он показывает устройство нескольких практик AI Mindset на **вымышленных данных** и даёт минимальные исходники, которые можно перенести в свой проект. Начните с одной задачи, затем подставьте свои домены, контент, репозитории и ответственных.

| Задача | Что взять | Первый результат |
|---|---|---|
| Уведомлять команду о заявках | [Лид → бот](lead-to-bot/README.md) | локальный приёмник заявки с сухим прогоном и проверками |
| Обновлять общий блок сразу в нескольких сайтах | [Родитель и дочерние репозитории](shared-sites/README.md) | конфигурация дочерней страницы с точным пином родителя |
| Делать несколько страниц с общим каркасом и править текст | [Редактируемые страницы](editable-pages/README.md) | локальная страница и редактор, пишущий в исходный JSON |
| Видеть состояние сайта и историю проверок | [QA-дашборд](qa-dashboard/README.md) | открываемый отчёт с синтетическими результатами |

## Как работать с набором

1. Скопируйте нужную папку в свой репозиторий, сохранив её README и примеры данных.
2. Замените синтетические названия и URL, заполните переменные окружения **вне git**.
3. Выполните локальные проверки из README выбранного блока.
4. Назначьте владельца, который будет принимать ошибки доставки, обновлять родительский блок и разбирать QA-сигналы.
5. Для публикации добавьте свою инфраструктуру и отдельный релизный процесс. Локальный пример не является готовым публичным сервисом.

Папка `web/` в корне этого репозитория — демонстрационный интерфейс маркетинг-спринта. `kit/` — исходный набор спринта. Этот микрохарнесс — самостоятельные учебные примеры рядом с ними; добавление файлов сюда само по себе не меняет сайт, сценарий Demo или рабочие боты AI Mindset.

## Маршрут для агента

Перед настройкой прочитайте README выбранного блока и [SOURCE-MAP.md](SOURCE-MAP.md). Спросите у владельца только недостающие значения: домены, владельцев репозиториев, чат для уведомлений, доступный серверный хостинг и правила работы с персональными данными. Сначала используйте синтетический пример и сухой прогон. Показывайте отдельно: локальную проверку, коммит, публикацию и живую доставку. Не переносите внутренние токены, chat ID, реальные заявки или отчёты в публичный репозиторий.

[Отчёт о составе набора и границах переноса](REPORT.md) фиксирует, что найдено в существующем репозитории и что добавлено для студентов.

## Что здесь сознательно оставлено пустым

- бренд, шрифты и цвета — заполняются в [шаблоне дизайн-системы](../web/design-system-template/);
- домены, токены и получатели — задаются владельцем проекта;
- облачный деплой, очередь доставки и авторизация редактора — зависят от инфраструктуры команды;
- реальные QA-результаты — заменены синтетическими данными.
