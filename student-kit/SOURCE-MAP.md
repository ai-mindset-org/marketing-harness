# Карта переноса и границы примеров

Эти материалы основаны на изучении локальных исходников AI Mindset и существующего маркетингового харнесса. В публичный набор перенесены **паттерны и контракты**, а не внутренние данные или рабочие сервисы.

| Учебный блок | Изученный источник | Что адаптировано | Что не переносилось |
|---|---|---|---|
| Лид → бот | Сайт AI Mindset: клиентская форма, `/api/payment/site-contact`, серверный прокси и Cloud Run Telegram relay | разделение формы, серверного приёмника и бота; валидация, статусы доставки | токены, chat ID, реальные лиды, маршруты получателей, боевой relay |
| Общие блоки | `aim-aimindset.org-site-blocks` и дочерний `aim-aimindset.org-site` | один владелец блока, точный commit SHA, настройки экземпляра, проверка сборки | исходный фирменный header/footer, приватные дочерние страницы |
| Редактируемые страницы | исходники Human Lab: упорядоченные блоки, общий контент, данные страницы; локальный скилл `site-edit-overlay-builder/assets/editor-overlay-kit/` | runtime и CSS overlay перенесены из скилла; адаптер сохраняет видимый текст в исходный журнал с проверкой ревизии | контент лаборатории, приватные URL, код её действующего сервера |
| QA-дашборд | AIM Site Agent Evaluation: `report.json`, генератор статических страниц и история | схема отчёта, сводка, статусы и ссылки на доказательства | реальные проверки, снимки экранов, внутренние адреса, расписание и права доступа |

## Что показывает текущий репозиторий

Корневой `README.md` описывает маркетинг-спринт n25: `kit/` содержит его контекст, роли и упражнения; `web/` показывает Demo/Local/Team. Страница дизайн-системы уже добавлена отдельно. Микрохарнесс остаётся отдельным учебным слоем, чтобы не переписывать сценарий спринта и не выдавать примеры за действующую инфраструктуру.

## Проверка перед применением в другой команде

1. Сверьте каждый пример с актуальным рабочим репозиторием владельца: контракты и версии могли измениться.
2. Подставьте свои данные и проверьте обработку ошибок, приватность, права доступа и откат.
3. Зафиксируйте, где лежит исходник, что генерируется, какой SHA опубликован и кто получает сигнал об ошибке.
4. Не называйте успешный HTTP-ответ подтверждением доставки сообщения или прохождением QA. Сохраняйте фактический результат.

Полезные первичные источники: [Telegram Bot API](https://core.telegram.org/bots/api), [секреты Cloud Run](https://docs.cloud.google.com/run/docs/configuring/services/secrets), [повторно используемые GitHub Actions workflows](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows).
