# Лид с сайта → сервер → Telegram

```
форма сайта → POST /lead → проверка и журнал результата → Telegram sendMessage → статус доставки
```

На сайте AI Mindset форма собирает контакт и контекст страницы, отправляет их на собственный API, а серверный relay маршрутизирует уведомление в Telegram. Публичная страница не хранит токен бота. Этот пример повторяет **схему**, не рабочую маршрутизацию AI Mindset.

## Попробовать локально

Нужен Node.js 18+. Команды запускаются из этой папки:

```bash
node --test relay.test.mjs
ALLOWED_ORIGIN=http://localhost:4173 node relay.mjs
```

По умолчанию сервер слушает только `127.0.0.1:8787` и работает в режиме `dry-run`: ничего не отправляет в Telegram. Пример запроса:

```bash
curl -i http://127.0.0.1:8787/lead \
  -H 'Content-Type: application/json' \
  -H 'Origin: http://localhost:4173' \
  -d '{"id":"sample-001","name":"Учебный лид","contact":"student@example.test","page":"/course","consent":true}'
```

Успех в сухом прогоне означает только то, что запрос принят и проверен. Для живой отправки нужен серверный процесс с `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `LIVE_SEND=1` и разрешённым origin. Создайте бота через [BotFather](https://core.telegram.org/bots/features#creating-a-new-bot). В приватном чате получатель сначала открывает бота и нажимает Start; для группового чата добавьте бота в группу и отправьте тестовое сообщение. На новом боте chat ID можно получить из [`getUpdates`](https://core.telegram.org/bots/api#getupdates), прочитав `message.chat.id` **серверным** запросом. Если у бота уже настроен webhook, используйте входящий update webhook вместо `getUpdates`. Зафиксируйте разрешённый список chat ID и проверьте тестовую доставку в правильный чат.

Храните токен в секретах хостинга, например [Cloud Run Secret Manager](https://docs.cloud.google.com/run/docs/configuring/services/secrets), никогда в клиентском JS или git. Укажите `HOST=0.0.0.0` только в защищённом серверном окружении; для публичного приёмника добавьте инфраструктурные ограничения доступа, долговечную очередь, мониторинг и правила хранения персональных данных. Проверка заголовка Origin в примере не является аутентификацией: HTTP-клиент может его подделать.

## Контракт формы

| Поле | Смысл |
|---|---|
| `id` | идентификатор попытки; нужен для связывания событий и повторов |
| `name`, `contact` | данные, которые пользователь согласился передать |
| `page` | путь страницы, где оставлена заявка |
| `consent` | явное согласие в данном учебном контракте |

Форма отправляет запрос на **свой** same-origin API; серверный прокси может переправить его в relay. На клиенте это может выглядеть так:

```js
const result = await fetch('/api/lead', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ id, name, contact, page: location.pathname, consent: true }),
});
if (!result.ok) showRetryMessage();
```

`showRetryMessage()` здесь обозначает функцию вашего интерфейса, а `/api/lead` — маршрут вашего same-origin прокси. Настройте HTTPS, CORS/origin, ограничение размера, rate limit и антиспам до приёма реальных заявок. Разделяйте контакты (`/lead`) и события без контакта (`/event`); аналитические события не должны отправляться как лиды.

## Доставка и эксплуатация

Пример возвращает `delivered`, `dry_run` или `failed`; `dry_run` не является доставкой. Ошибка Telegram возвращает 502 с коротким кодом без вывода контакта в лог. В примере нет постоянной очереди и долговечной дедупликации: после перезапуска повтор `id` может создать ещё одно сообщение. Для рабочей системы добавьте хранилище статусов, ключ идемпотентности, ретраи с ограничением, отдельный алерт о неудачах и правила для частичной доставки при нескольких получателях. HTTP 202 от промежуточного API означает принятие в обработку, а не подтверждение сообщения в чате.

## Проверки перед живым запуском

- Разрешённый origin и валидное тело проходят в `dry-run`.
- Чужой origin, отсутствующее согласие, лишние поля и большой запрос отвергаются.
- При неверном токене и ошибке Telegram статус остаётся `failed`.
- В клиенте и логах нет токена, полного контакта или chat ID.
- Повторная заявка, остановленная доставка и недоступный бот видны ответственному человеку.
