# Страницы с общим каркасом и локальным редактированием

В изученном примере Human Lab страницы собираются из упорядоченных блоков, общего контента и данных конкретной страницы. Локальный редактор меняет исходник, после чего страница пересобирается. Ниже — маленький самостоятельный вариант той же идеи с **синтетическим** курсом.

## Запуск

```bash
node --test editor.test.mjs
node editor.mjs
```

Откройте `http://127.0.0.1:8790/` для страницы курса и `http://127.0.0.1:8790/?page=sample-event` для страницы события. Сервер слушает только localhost. Если порт занят, задайте `PORT=8791` после проверки свободного порта. Страница и форма правки живут в одном локальном интерфейсе.

Создать третью страницу с тем же каркасом:

```bash
node new-page.mjs my-workshop "Практика воркшопа" "Спланируйте встречу и соберите результаты команды."
```

Команда создаёт `pages/my-workshop.json` и пустой `pages/my-workshop.edits.jsonl` без перезаписи существующих файлов. Адрес редактора будет `http://127.0.0.1:8790/?page=my-workshop`. Общие подписи и результаты по-прежнему берутся из `shared.json`; порядок секций — из данных каждой страницы.

## Где лежит исходник

- `page.json` и `pages/*.json` — исходная композиция и начальный текст отдельных страниц. Порядок `blocks` определяет порядок секций.
- `shared.json` — общие подписи и навигация для серии страниц.
- `edits.jsonl` и `pages/*.edits.jsonl` — отдельные журналы правок. Сохранение **добавляет** событие, не перезаписывая старый текст. Для отката добавьте новую правку с прежним значением или вернитесь к нужной версии через git.
- `editor.mjs` — локальный рендерер и редактор. Он позволяет менять только три поля, проверяет ожидаемую ревизию и не принимает произвольный HTML.

Общий каркас остаётся в рендерере и `shared.json`, а локальная копия текста — в данных страницы. В полноценной системе перед записью нужен пробный рендер, схема для каждого блока, права пользователя, серверная защита от конфликтов и проверки после экспорта.

## Что проверить после адаптации

1. Изменение текста одного блока не меняет другие страницы и общий header/footer.
2. Два редактора не затирают друг друга: запрос со старой `revision` получает `409`.
3. Некорректный текст не попадает в HTML как код; значение экранируется.
4. После обновления страницы изменения остаются, а git показывает событие правки.
5. Публичная версия строится из принятого исходника; локальный редактор не публикуется как открытый endpoint.

Этот пример специально не содержит облачной авторизации и не предназначен для публичного запуска. Исторические редакторы и пайплайны AIM не являются частью этого шаблона.
