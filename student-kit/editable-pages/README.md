# Страницы с общим каркасом и локальным редактированием

В изученном примере Human Lab страницы собираются из упорядоченных блоков, общего контента и данных конкретной страницы. Здесь для редактирования используется **реальный runtime из локального скилла `site-edit-overlay-builder`**, а данные страниц — синтетические. Код runtime перенесён в [`overlay/`](overlay/); изменены только русские подписи панели. [`overlay-adapter.js`](overlay-adapter.js) связывает его с исходными JSON и журналом.

## Запуск

```bash
node --test editor.test.mjs
node editor.mjs
```

Откройте `http://127.0.0.1:8790/` для страницы курса и `http://127.0.0.1:8790/?page=sample-event` для страницы события. Сервер слушает только localhost. Если порт занят, задайте `PORT=8791` после проверки свободного порта.

В нижней панели нажмите **«Редактировать»**, затем кликните прямо по нужному тексту и исправьте его на странице. Можно менять заголовок, введение, подписи навигации, текст кнопки, пункты списка и другие видимые авторские строки. Маркеры позволяют переставлять секции и пункты списка. Нажмите **«Сохранить»**, затем обновите страницу: правка должна остаться. У панели есть статус сохранения или ошибки.

Создать третью страницу с тем же каркасом:

```bash
node new-page.mjs my-workshop "Практика воркшопа" "Спланируйте встречу и соберите результаты команды."
```

Команда создаёт `pages/my-workshop.json` и пустой `pages/my-workshop.edits.jsonl` без перезаписи существующих файлов. Адрес редактора будет `http://127.0.0.1:8790/?page=my-workshop`. Общие подписи и результаты берутся из `shared.json`; порядок секций и соответствующей навигации — из данных каждой страницы.

## Где лежит исходник

- `page.json` и `pages/*.json` — исходная композиция и начальный текст отдельных страниц. Порядок `blocks` определяет порядок секций.
- `shared.json` — общие подписи навигации и результаты для серии страниц; порядок ссылок при показе следует порядку секций конкретной страницы.
- `edits.jsonl` — общий журнал сохранений overlay: одна запись содержит изменения конкретной страницы и общего контента. Сохранение **добавляет** событие, не перезаписывая старый текст. Пустые `pages/*.edits.jsonl` оставлены для чтения правок из первого учебного прототипа; новые сохранения идут в общий журнал.
- `editor.mjs` — локальный рендерер и ограниченный endpoint сохранения. Он проверяет ревизию, список полей и порядок блоков, затем записывает новое событие в журнал.
- `overlay/site-edit-overlay-runtime.js` и `.css` — исходная обвязка скилла для клика по видимому тексту, защиты интерактивных элементов и перетаскивания блоков.
- `overlay-adapter.js` — соответствие видимого текста полям `page.json`/`shared.json` и запрос на сохранение.

Общий каркас остаётся в рендерере и `shared.json`, а локальная копия текста — в данных страницы. Изменение общего текста одной страницы появится и на другой после обновления. В полноценной системе перед записью нужен пробный рендер, схема для каждого блока, права пользователя и проверки после экспорта.

## Что проверить после адаптации

1. Изменение локального текста одной страницы не меняет другую; изменение общего текста отражается на обеих.
2. Два редактора не затирают друг друга: запрос со старой `revision` получает `409`.
3. Некорректный текст не попадает в HTML как код; значение экранируется.
4. После обновления страницы изменения остаются, а git показывает событие правки в `edits.jsonl`.
5. Публичная версия строится из принятого исходника; локальный редактор не публикуется как открытый endpoint.

Этот пример специально не содержит облачной авторизации и не предназначен для публичного запуска. Исторические редакторы и пайплайны AIM не являются частью этого шаблона.
