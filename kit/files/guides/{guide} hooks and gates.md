# хуки и гейты

Правило говорит агенту, как поступать. Гейт останавливает действие, если правило нарушено. Харнесс держит оба слоя: правила в `rules/`, гейты в `gates/` и в коде `bin/`.

## что такое хук

Хук – команда, которую программа запускает сама в заданный момент. Claude Code читает список хуков из `.claude/settings.json` и передаёт команде JSON на stdin.

| событие Claude Code | когда наступает | пример применения |
|---|---|---|
| `SessionStart` | сессия началась или возобновилась | подтянуть правила, напомнить про давний прогон проверок |
| `UserPromptSubmit` | человек отправил запрос | записать цель сессии из первого запроса |
| `PreToolUse` | перед вызовом инструмента (Write, Edit, Bash) | остановить запись или команду |
| `PostToolUse` | после вызова инструмента | записать правку в журнал |
| `Stop` | агент закончил ответ | отметить, что задача доведена до результата |
| `SessionEnd` | сессия закрыта | выгрузить итог в память |

В git те же идеи живут файлами в `.githooks/`: `pre-commit` срабатывает перед коммитом, `pre-push` перед отправкой на сервер. Включение: `git config core.hooksPath .githooks`.

## чем гейт отличается от правила

Правило – текст в `AGENTS.md` или `rules/`. Агент его читает и обычно выполняет. Гейт – код на хуке `PreToolUse` или `pre-commit`: он отвечает «нельзя» до того, как действие случилось, и агент не может его пропустить рассуждением. Критичное правило (ключи, публикация, статус `approved`) получает гейт, мелкое остаётся текстом.

## блок двумя каналами

Гейт сообщает отказ двумя способами сразу, потому что разные версии клиентов читают разные каналы.

1. Код выхода 2 и объяснение в stderr: `process.stderr.write(...)`, затем `process.exit(2)`.
2. JSON на stdout:

```json
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"причина для агента"}}
```

Причина пишется так, чтобы агент понял следующий шаг: «запусти `node bin/check.mjs`, поправь провалы, повтори». Образец: `bin/gate-approved.mjs`.

## обёртка в settings без `|| true`

Команда в `.claude/settings.json` запускает скрипт напрямую: `node bin/gate-approved.mjs`. Конструкция вида `[ -f "$G" ] && bash "$G" || true` превращает код 2 в код 0: блок исчезает, а проверка выглядит зелёной. У команды AI Mindset так остановился гейт: живые сессии читали закрытую папку при полностью зелёной матрице тестов. Если нужна проверка «файл существует», пиши `if [ -f "$G" ]; then bash "$G"; fi`: код возврата скрипта сохраняется.

## тест гейта через ту же обёртку

Гейт проверяется командой из settings, а не голым скриптом. `node bin/gate-tests.mjs` читает команду из `.claude/settings.json`, гоняет её на шести случаях во временной папке и печатает матрицу PASS/FAIL. Новый гейт получает строки в этой матрице в тот же день. Проверка блока включает оба канала: код 2, текст в stderr, JSON на stdout.

## выключатели

У каждого гейта есть переменная окружения, которая его пропускает (у набора это `HARNESS_GATE_OK=1`). Включает выключатель только человек, словом в этой сессии, и на одну задачу. Агент выключатель не ставит, не предлагает и не обходит переименованием файла. Причину обхода человек называет вслух, чтобы её можно было вспомнить.

## как это устроено у команды AI Mindset

У команды хуки покрывают весь рабочий день агента:
- на старте сессии подтягиваются базовые правила команды, офлайн старт не падает;
- гейт чужой папки черновиков останавливает чтение и запись в личное пространство другого участника, а своя папка открыта; имена папок берутся из реестра карточек ролей;
- гейт «сначала спроси карту контура» перед созданием машины, сервиса или воркфлоу требует найти существующий узел и владельца;
- секрет-скан стоит на коммите и ещё раз перед отправкой на сервер;
- первый запрос сессии становится её целью; когда задача доведена, ответ заканчивается строкой «можно закрывать», хук `Stop` отмечает готовность, вкладку закрывает человек;
- гейты тестируются матрицей PASS/FAIL через ту же обёртку, что записана в настройках.

## что дальше

1. Включи git-хук: `git config core.hooksPath .githooks` и `brew install gitleaks`.
2. Прогони `node bin/gate-tests.mjs`: ждём `все 6 PASS`.
3. Добавь недостающие гейты по одному, каждый со строкой в матрице. Новое правило и скилл добавляются по [[{skill} harness-evolve]].
