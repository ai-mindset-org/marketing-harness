# автоматизация харнесса

Три уровня: от сессии руками до сервера команды. Начинай с первого и поднимайся, когда задача повторилась три раза подряд.

## три уровня
| уровень | как запускается | где живёт | когда брать |
|---|---|---|---|
| 1 · руками в сессии | человек пишет «Прочитай AGENTS.md. По скиллу …» | `claude` или `codex` внутри папки | первые недели, любая новая задача |
| 2 · рутина на своём компьютере | Claude Desktop (рутина по расписанию) или cron + `claude -p` | компьютер человека, должен быть включён | ежедневная задача с маленьким входом: [[{automation} daily linkedin]], [[{automation} trend scan]] |
| 3 · сервер команды | Сотник: `codex exec --full-auto` из консоли харнесса или по таймеру | сервер команды, копия папки `~/harness/<имя>` | задача идёт ночью, компьютер выключен, ключи нужны на сервере ([[{tool} codex]]) |

Третий уровень доступен команде AIM. Своя копия на своём сервере строится так же: папка под git, ключи в окружении, один таймер на задачу.

## одна задача – один планировщик
Каждая повторяющаяся задача имеет ровно один запускатель и одного владельца. Второй запускатель на ту же задачу даёт двойные комментарии, двойные списки и двойной расход.
1. Выбери уровень для задачи.
2. Впиши в паспорт автоматизации строки «планировщик» и «владелец» (образец – три файла ниже).
3. Переезд на другой уровень: сначала выключи старый запускатель, потом включи новый, в журнал запусков две строки подряд.
4. Раз в месяц просмотри паспорта: у кого нет владельца, тот выключается ([[{skill} harness-principles]]).

## журнал запусков
Каждый прогон оставляет след, иначе тихо упавшая рутина заметна через неделю.
- одна строка на запуск в `dashboards/{dashboard} runs – <дата начала недели>.md`: время · автоматизация · исполнитель · результат (файл или ошибка);
- строку пишет сама команда запуска (`echo "$(date +%F\ %H:%M) daily-linkedin claude-p ok" >> …`) или скилл последним шагом;
- лог процесса лежит вне папки: `~/.harness-logs/<имя>.log`;
- коммит на прогон: `git add -A && git commit -m "daily-linkedin: список 2026-09-30"` ([[{rule} principles]], пункт 12);
- в пятничном срезе строка «пропущенные запуски»: [[{automation} weekly loop]].

## человек утверждает публикацию
Автоматизация готовит файл со статусом `draft`. Публикация, рассылка, комментарий, платная реклама идут после `approved` от человека ([[{rule} boundaries]]). Пропуск шага одобрения считается сбоем автоматизации: рутина выключается до разбора.

## минимум безопасности
- ключи в `~/.zshrc` или менеджере паролей; в папке и git их нет;
- у `claude -p` список `--allowedTools` короткий: чтение, запись в папку, `node bin/*`, `git status`, `git add`, `git commit`;
- токен LMS только для чтения, токен LinkedIn только `w_member_social`;
- рутина, которая пишет наружу без человека, в харнесс не заводится.

## три готовые автоматизации
- [[{automation} daily linkedin]] – утро, будни, список на модерацию;
- [[{automation} trend scan]] – каждый день в 11:00, таблица залётов;
- [[{automation} weekly loop]] – пятница, срез недели и находки для правил.

Роли, которые исполняют эти задачи, описаны в [[{role} agent crew]].
