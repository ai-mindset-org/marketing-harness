# как сетапить скилл

Скилл – рецепт одной повторяющейся задачи. Пример по шагам: `email-digest`, письмо-дайджест недели для базы подписчиков (формат F6 из [[{rule} creative-codes]]). Тот же порядок подходит для любого скилла. Общий принцип разделения правил и скиллов – [[{guide} rules to skills]].

## шаг 1 · проверь дубль
```bash
node bin/guard-new.mjs skill email-digest
```
Команда ищет в `skills/` файлы с теми же словами в имени ([[{gate} ask before create]]). Если найден файл со словом «digest» или «email» – читай его: письмо могло уже жить внутри него. Код возврата 0 – имя свободно. Код 1 – дополни найденный файл.

## шаг 2 · создай файл
`skills/{skill} email-digest.md`. Имя латиницей, слова через дефис, тип в фигурных скобках ([[{rule} naming]]). Единый источник – эта папка. Зеркала для Claude Code и Codex появятся на шаге 4.

## шаг 3 · заполни файл
```
---
name: email-digest
description: Use when нужно собрать письмо-дайджест недели из проверенных черновиков. Триггеры – дайджест, письмо базе, рассылка недели, email digest.
---
# email-digest

письмо из 3–4 проверенных единиц недели: одна мысль на блок, один CTA.

1. вход: `dashboards/` последний срез, нуклеусы со статусом reuse, черновики со статусом checked
2. выбери 3–4 единицы с вердиктом winner или testing; fake_winner в письмо не идёт
3. на каждую единицу – блок 40–70 слов по голосу [[{context} voice]], код креатива в ссылке
4. проверки: `node bin/check.mjs`, затем [[{skill} slop-check]] в отдельном контексте
5. выход: `outputs/email/{post} em-01 week digest.md`, статус draft; публикует человек
6. ссылки: [[{rule} anti-slop]] · [[{rule} creative-codes]] · [[{context} voice]]
```
Что стоит в каждом поле:
- `name` совпадает с именем файла без типа;
- `description` начинается с «Use when» и содержит слова, которыми человек просит задачу: по ним агент выбирает скилл;
- шаги – по одному действию, у шага проверяемый результат;
- вход и выход названы файлами и папками;
- правила подключены ссылками: голос, [[{rule} anti-slop]], [[{rule} creative-codes]]. Тексты правил в скилл не копируются, правка в `rules/` доходит до скилла сама.

Длина 20–40 строк. Больше – скилл делает две задачи, режь на два.

## шаг 4 · синхронизируй зеркала
```bash
node bin/sync-skills.mjs
```
В `.claude/skills/email-digest/SKILL.md` и `.agents/skills/email-digest/SKILL.md` появляются копии с пометкой «mirror». Зеркала руками не правятся: следующий запуск их перезапишет.

## шаг 5 · свяжи с роутером
В [[AGENTS]] в разделе «какой скилл когда» добавь строку: `письмо базе → email-digest`. Роутер и description работают вместе: description помогает найти скилл среди рецептов, строка роутера закрепляет выбор для типовой задачи. Правку роутера предлагает агент через [[{skill} harness-evolve]], принимает человек.

## шаг 6 · проверь
1. В Claude Code набери `/`: `email-digest` виден в списке. Нет в списке – перезапусти сессию и проверь, что зеркало создано.
2. Прогон на одном нуклеусе: «по скиллу email-digest собери письмо недели, вход – срез 29.09». Смотри, все ли шаги выполнены и лежит ли файл выхода где сказано.
3. Добавь в [[{eval} golden-set]] строку: одно хорошее письмо и одно плохое (длинное тире, два CTA, цифра без источника).
4. `node bin/check.mjs --golden`: хорошее проходит, плохое падает на конкретном правиле.
5. Балл критика 80 и выше – скилл принят.

## как агент выбирает скилл
1. Сессия стартует с [[AGENTS]] и списком скиллов: у каждого в контексте лежат `name` и `description`.
2. Просьба человека сопоставляется с description: триггерные слова из description дают совпадение.
3. Роутер в AGENTS.md разрешает спор, когда подходят два скилла.
4. Выбранный скилл читается целиком, ссылки на правила подгружают правила.

## частые ошибки
| ошибка | признак | как исправить |
|---|---|---|
| скилл-энциклопедия | больше 60 строк, три задачи в одном | режь по задачам, общее – в правило |
| нет выхода | шаги есть, файл нигде не назван | добавь строку «выход» с именем и папкой |
| дубль правила | текст anti-slop скопирован в скилл | оставь ссылку, копию удали |
| description без триггеров | агент не находит скилл по просьбе | впиши слова, которыми просит человек |
| правка зеркала | изменение пропало после sync | правь `skills/`, затем `node bin/sync-skills.mjs` |
| скилл без эталона | нет строки в golden set | добавь хороший и плохой пример |
