# гейт – секрет-скан перед коммитом

Ни один ключ, токен или пароль не попадает в историю git. Одна утечка в коммите живёт в истории навсегда, даже после удаления файла.

## что проверяет
- `gitleaks protect --staged --redact`: сканирует только то, что стоит в коммите, и прячет найденное значение в выводе;
- шейпы токенов: токен бота Telegram (`<цифры>:<строка>`), ключи с префиксом `sk-`, `Bearer eyJ…`, `api_hash`, приватные ключи `.pem`;
- размер: файл больше 50 МБ в коммит не идёт (видео и архивы живут вне git).

## когда срабатывает
Событие `git commit`: скрипт `.githooks/pre-commit`. Без gitleaks гейт печатает предупреждение и пропускает секрет-скан, поэтому установка обязательна.

## как включить
1. `brew install gitleaks`;
2. `git config core.hooksPath .githooks` (один раз на клон);
3. `chmod +x .githooks/pre-commit`, если файл потерял бит запуска.

## как проверить
Положи в тестовый файл строку вида `token = "sk-" + 40 случайных символов`, выполни `git add` и `git commit`. Коммит должен остановиться с сообщением gitleaks. Потом убери файл из индекса: `git restore --staged <файл>`.

## что делать при срабатывании
1. Считай ключ скомпрометированным и перевыпусти его в сервисе.
2. Убери значение из файла, положи в переменную окружения или менеджер паролей.
3. Добавь файл заново обычным коммитом.
4. Если ключ уже ушёл в `git push`, скажи человеку: история переписывается вместе с ним. «Тихий amend» ключ не отзывает.

## выключатель
`git commit --no-verify` пропускает все проверки хука. Только по слову человека, и ключ после этого всё равно перевыпускается.

## откуда
