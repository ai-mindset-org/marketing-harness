# гейт – `status: approved` только после зелёных проверок

Статус `approved` во frontmatter черновика в `outputs/` означает «прошёл проверки кодом». Гейт не даёт записать этот статус, пока свежий отчёт `node bin/check.mjs` не показывает `pass` для этого файла.

## что проверяет
- запись затрагивает `outputs/**/*.md` и содержит строку `status: approved`;
- в самом новом файле `evals/{eval} checks – <дата>.md` есть строка `[[<имя файла без .md>]]`;
- итог в строке равен `pass`. `warn` и `fail` блокируют запись; отчёта нет – тоже блок.

## когда срабатывает
Событие PreToolUse Claude Code на инструменты `Write` и `Edit`. Для Write гейт читает `content`, для Edit – `new_string`. Скрипт: `bin/gate-approved.mjs`.

## как включить
Хук уже записан в `.claude/settings.json` (matcher `Write|Edit`, команда `node bin/gate-approved.mjs`). Claude Code читает файл при старте сессии; после правки перезапусти сессию. Подробности: [[{guide} hooks and gates]].

## как проверить
`node bin/gate-tests.mjs` прогоняет шесть случаев через ту же команду, что в settings, во временной папке, и седьмым проверяет, что pre-commit исполняемый и включён (`core.hooksPath .githooks`). Ожидаемый итог: `все 7 PASS`.

## выключатель
`HARNESS_GATE_OK=1` в окружении сессии пропускает запись. Включает только человек и только на одну задачу; агент выключатель не ставит и не предлагает.

## откуда
У команды AI Mindset так устроен путь к публикации: детерминированная проверка бренд-голоса и фактов идёт до человека, а статус готовности стоит за гейтом. Уровни проверок: [[{rule} evals]]. Граница ролей: [[{rule} boundaries]].
